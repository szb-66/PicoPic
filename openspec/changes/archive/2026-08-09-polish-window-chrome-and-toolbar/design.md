## Context

当前 Tauri 窗口保留 Windows 系统装饰，React 内部又渲染一条品牌头部；头部右侧的“更多选项”按钮无事件处理，底部命令按钮采用两行网格却只显示一行文字，造成图标和文字组合在视觉上偏离底栏中线。窗口控制需要兼顾 Tauri 运行时、浏览器开发预览和单元测试。

## Goals / Non-Goals

**Goals:**

- 用一条品牌化自绘标题栏同时承担窗口拖动与窗口控制。
- 将桌面窗口调用隔离在可替换边界内，使 React 测试不依赖真实 Tauri 窗口。
- 用单行 flex 命令按钮消除底栏的隐式空网格行。

**Non-Goals:**

- 不新增应用级菜单、关于页或重复的设置入口。
- 不改变任务列表、压缩队列或设置数据模型。
- 不改变 Sites 构建的后端适配层。

## Decisions

### 将现有应用头部升级为标题栏

关闭 Tauri 的系统 decorations，并将现有品牌区标记为拖动区域；右侧使用三个显式窗口控制按钮。这样避免额外增加一条标题栏导致内容高度减少，也不会重复展示品牌。备选方案是保留系统标题栏仅换主题，但 Windows 原生标题栏无法与应用的间距、颜色和控件风格完全一致。

### 通过窗口操作适配器调用 Tauri API

新增小型窗口操作边界，封装最小化、最大化切换与关闭。浏览器开发预览中返回安全的无操作实现，Tauri 中才加载当前窗口对象。相比直接在组件里调用全局窗口 API，此方案更容易测试，也不会让 Sites 预览产生运行时错误。

### 删除“更多选项”而不是创造重复菜单

该按钮没有既定功能，现有底栏已经提供设置入口。删除用途不明的控件比新增只包含“设置”的菜单更直接，并满足每个可见控件都有明确作用的要求。

### 底栏命令改用单行 flex

命令图标和文字是同一行语义，不需要两行网格。按钮与命令组都使用 `align-items: center` 并占满底栏可用高度，使常规与紧凑断点共用同一垂直对齐模型。

## Risks / Trade-offs

- [无系统标题栏后窗口操作完全依赖自绘控件] → 保留明确的拖动区域、双击最大化行为和三个标准窗口按钮，并配置最小化、最大化和关闭权限。
- [开发浏览器不具备桌面窗口] → 适配器在非 Tauri 环境安全降级，视觉结构仍可验证。
- [拖动区域吞掉按钮交互] → 只给非交互品牌/空白区添加拖动属性，窗口按钮显式排除拖动。

## Migration Plan

更新 Tauri 窗口配置与权限后，在开发版启动主窗口验证拖动和三个窗口控制；若需回滚，恢复系统 decorations 并移除自绘控制区即可，不涉及用户数据迁移。
